# 02 · 接口契约（要点与校验）

> **唯一真相**：[`00-项目基线-MVP.md`](00-项目基线-MVP.md) **§10**（§10.1 通用约定 / §10.2 错误码表 / §10.3 接口清单 + 三个关键示例）。
> 本文只讲"怎么读、怎么验、改接口怎么走"。字段级出入参由 FastAPI 自动生成 OpenAPI，**禁止手写契约**。
> 可运行产物：`http://127.0.0.1:8000/docs`（Swagger）、`http://127.0.0.1:8000/openapi.json`。

## 1. 通用约定（§10.1，前端 `.env` 与 axios 拦截器都依赖这些）

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1`（`API_PREFIX`，见 `.env.example`） |
| 命名 | JSON 一律 `snake_case`，前端在 `types/` 层做映射，不做运行时转换 |
| 鉴权 | `Authorization: Bearer <jwt>`；JWT payload = `{sub, email, exp, iat}` |
| 工作区 | `X-Workspace-Id: <id>`（可选；缺省用默认工作区） |
| 成功响应 | 直接返回资源对象或分页对象，**不套** `code/data` |
| 分页 | `?page=1&page_size=20`（1 起，≤100）；响应 `{items,total,page,page_size}` |
| 排序 | `?sort=-risk_score,created_at`（`-` 倒序；白名单字段，非法字段 400） |
| 时间 | 出入参 ISO8601 UTC（`2026-09-30T11:05:00Z`）；前端负责转 Asia/Shanghai |
| 错误 | HTTP 语义状态码 + `{"error":{"code","message","details"}}`（ADR-A12） |
| 幂等 | 写操作（PATCH / resolve / close / approve）必须带 `expected_version`，不匹配 → 409 |
| 追踪 | 响应头 `X-Request-Id`（同时写审计日志） |
| 限流 | 演示级：AI 分析 1 次/5 秒（429 `RATE_LIMITED`），其余不限 |

## 2. 错误码（§10.2 全表，此处只列最常用的 8 个）

| code | HTTP | 什么时候会遇到 |
|---|---|---|
| `AUTH_INVALID_CREDENTIALS` | 401 | 账号/密码错误 |
| `PERM_DENIED` | 403 | 角色权限不足（如 VIEWER 写操作） |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在**或跨租户**（越权一律 404，不泄露存在性） |
| `VALIDATION_ERROR` | 422 | 入参校验失败（`details.fields`） |
| `STATE_TRANSITION_INVALID` | 409 | 状态机不允许的流转（`details.from/to`） |
| `OPTIMISTIC_LOCK_CONFLICT` | 409 | `expected_version` 不匹配（有人先改了） |
| `AI_OUTPUT_INVALID` | 502 | LLM 输出两次都没过 schema 校验 |
| `LLM_UNAVAILABLE` | 503 | 模型不可达/超时/超额，已降级（异常仍可人工处理） |

完整 18 条见 §10.2；`KNOWLEDGE_EMPTY` 不是错误（返回空数组 + 提示）。

## 3. 接口分组（§10.3，共 12 组）

```text
【认证】      /auth（register / login / me / logout）
【工作区】    /workspaces（含 current / members）
【主数据】    /customers /carriers /vehicles /drivers（列表支持 q/status/level/sort/page）
【订单】      /orders（详情含客户/承运商/车辆/司机摘要 + SLA 快照 + 当前异常摘要；tracking-events 写入会触发 ETA 重算与检测）
【SLA 规则】  /sla-rules
【异常】      /exceptions（confirm / analyze / resolve / close / events / messages）
【AI 分析】   /ai-analyses（前端每 1.5s 轮询状态与 steps 进度；FAILED 可 retry）
【人工确认】  /approvals（approve / reject / batch-approve / execute 重试）
【跟进任务】  /followups
【通知】      /notifications（mark-sent 为 SENT_MOCK 模拟发送）
【Dashboard】 /dashboard/summary、/dashboard/trend
【审计/知识/系统】/audit-logs、/knowledge/*、/healthz、/demo/*
```

三个最关键的示例（`analyze` 202+轮询、`ai-analyses` 的 steps/risk_level、`approve` 的 diff+execution_result）见 §10.3 末尾，**不改口径**。

## 4. 硬规则（写代码时容易破）

1. **越权即 404**：Repository 统一带 `workspace_id` 过滤，不要返回 403 暴露资源存在性（§9.1）；
2. **状态变更走状态机**：路由只调 `services/state_machine.transition()`，禁止直接赋值 `status`，非法流转 409；
3. **AI 相关接口不写库**：`analyze` 只产生 `ai_analysis` + `approval`，业务副作用只在 `approvals/{id}/approve` 后的执行器里发生（§11.5）；
4. **响应不套壳**：前端 axios 拦截器按 HTTP 状态码与 `error.code` 处理，401 登出、409 提示"数据已更新"；
5. 新增接口后必须同步 `docs/openapi.json` 产物与前端 `types/`。

## 5. 可执行校验命令

```powershell
cd backend
uv run uvicorn app.main:app --reload            # http://127.0.0.1:8000/docs

# 健康检查（含 db / clock_mode / ai_mode）
curl.exe http://127.0.0.1:8000/healthz

# 导出 OpenAPI 交付物（docs/openapi.json 是 §15 交付物清单之一）
uv run python -c "import json;from app.main import app;open('../docs/openapi.json','w',encoding='utf-8').write(json.dumps(app.openapi(),ensure_ascii=False,indent=2))"

# 接口层测试（认证/RBAC/分页/乐观锁/错误码；conftest 自动用 sqlite 临时库）
uv run pytest tests/api -q

# 契约冒烟：登录拿 token，再带 X-Workspace-Id 访问一个列表接口
curl.exe -s -X POST http://127.0.0.1:8000/api/v1/auth/login -H "Content-Type: application/json" -d "{\"email\":\"owner@logiops.dev\",\"password\":\"Demo@12345\"}"

# 错误体形状断言（应为 {\"error\":{\"code\",...}}，HTTP 401）
curl.exe -i -s -X POST http://127.0.0.1:8000/api/v1/auth/login -H "Content-Type: application/json" -d "{\"email\":\"owner@logiops.dev\",\"password\":\"wrong\"}" | Select-String "error|401"
```

## 6. 与前端的对齐点

- 前端 `src/api/*` 只按 §10 路径与字段名取值，不自造字段；后端未就绪时用本地静态 fixture 渲染骨架（不空白报错）；
- 401 → 登出并跳登录；409 → 顶部提示"数据已更新，请刷新"；422 → 表单字段级错误；
- 演示横幅显示 `AI_MODE`（回放/实时）与业务时间，数据来自 `GET /healthz` 与 `GET /demo/state`。
