# 06 · 演示脚本（5 分钟，逐分钟）

> 台词与节奏以 [`00-项目基线-MVP.md`](00-项目基线-MVP.md) **§16** 为准；本文补"演示前怎么准备、翻车怎么恢复、每个动作对应哪个接口/CASE"。
> 相关：§13.3 五个脚本化案例、§13.4 Demo 控制接口、§17 效率度量协议（实测表见 `docs/demo-metrics.md`）。
> 核心口径一句话：**"这个项目的价值不是用了大模型，而是把 LLM 关进了可信的边界里。"**

## 1. 演示前 3 分钟检查清单（照着敲）

```powershell
# ① 起库 + 迁移 + seed（固定种子 20260930，幂等）
mysql -uroot -p < scripts/init_db.sql        # 首次才需要
pwsh -File scripts/seed.ps1 -InitSchema

# ② 起后端 + 前端（独立窗口）
pwsh -File scripts/dev.ps1

# ③ 自检：AI 必须是 replay（现场不联网、0 成本、结果确定）；时钟是真实时间
curl.exe -s http://127.0.0.1:8000/api/v1/healthz    # 期望 ai_mode=replay, clock_mode=system, db=true
#   浏览器打开 http://127.0.0.1:5173 ，用 owner@logiops.dev / Demo@12345 登录（演示用 operator 视角）

# ④ 演示前把状态推回初始
curl.exe -s -X POST http://127.0.0.1:8000/api/v1/demo/actions/reset -H "Authorization: Bearer <token>" -H "X-Workspace-Id: 1" -H "Content-Type: application/json" -d "{\"scenario\":\"case-a\"}"
```

用 `POST /api/v1/demo/actions/reset` 重置比任何手工改库都快；页面卡住就刷新（A7：前端 1.5s 轮询，不依赖长连接）。

## 2. 逐分钟脚本（§16 原样节奏）

> **演示前必读（与 README 顶部「当前实现状态」一致）**
> **AI 与 ETA 速度模拟已停用**（`AI_ENABLED=false` / `ETA_ENABLED=false`，见 `docs/08`）。
> - 下表中 **1:50–3:00「AI 分析」** 与 **3:00–3:40「消息解析 / 通知草稿」** 环节请改为讲：
>   「这套能力**保留在代码里、当前运行时不启用**」，并现场展示界面上的「AI 已停用（待重构）」提示（分析按钮已隐藏）。
> - **延误改为人工录入**：SLA 卡里填「预计送达」，程序按 `延误 = 预计送达 − 承诺到达` 提交，**是否违约由规则判定**（可现场演示改动时间后违约状态翻转）。
> - 想展示**完整可运行闭环**，请走：**建单 → 派车 → 录轨迹 → 自动检测建异常 → 人工录延误（规则判违约）→ 审批 → 执行 → 关闭 → 审计**。
> - CASE-A 的 seed 数值与「≤14 步」等 AI 口径仍可用于讲设计，但**不要声称演示时会真的调用大模型**。

| 时间 | 画面 | 动作 / 台词 | 接口 |
|---|---|---|---|
| 0:00–0:30 | 问题背景 | 跟单员异常时要跨 4~5 个系统核对信息，一票异常平均耗时 N 分钟 | — |
| 0:30–1:00 | 架构一页图 | Router→Service→Repository；AI 只读 Tool，写操作走审批（强调"AI 不碰库"） | — |
| 1:00–1:30 | Dashboard | operator 登录 → 异常数、SLA 违约数、高风险 Top5 | `GET /dashboard/summary` |
| 1:30–1:50 | 建单起点（可选，回答"数据哪来的"） | 运输订单页【新建订单】→ 选客户/起终地 → 创建后为「待发车」；进详情【派车】填承运商/司机/车辆 → **承诺到达时间由 SLA 规则自动算出**（发车 + 规则偏移），不是手填 | `POST /orders`、`PATCH /orders/{id}` |
| 1:50–3:00 | CASE-A 异常详情 | 轨迹时间线显示 19:00 起济南停滞 → 系统已自动建单且 `level=CRITICAL`；点【AI 分析】逐步点亮 7 个工具步骤；打开 `risk_factors` 面板说明"等级是规则算的" | `GET /exceptions/{id}`、`POST /exceptions/{id}/analyze`、`GET /ai-analyses/{id}`（1.5s 轮询） |
| 3:00–3:40 | 消息与草稿 | 粘贴承运商原文"车在济南爆胎了…预计晚上 8 点恢复"→ 解析结果与原文对照 → 生成客户通知草稿；**现场演示"喂假事实 → 被拦截"** | `POST /exceptions/{id}/messages`、T3 草稿 |
| 3:40–4:20 | 逐条审批 | 把 AI 建议的 ETA 从 22:30 手工改成 22:45 → 展示 diff → 批准 → 后端执行（ETA 更新、跟进任务、通知草稿、审计）一屏可见 | `GET /exceptions/{id}/approvals`、`POST /approvals/{id}/approve` |
| 4:20–4:50 | tick 推进（**演示页先把时钟切到「虚拟时钟」**） | 车辆恢复 → ETA 重算 → 订单送达 → 24h 后异常自动关闭；打开操作记录/审计看 `source`（MANUAL/APPROVED_AI/SYSTEM）。默认是真实时间模式（`CLOCK_MODE=system`），此时这两个接口返回 409 `DEMO_CLOCK_DISABLED`：在演示页点「虚拟时钟」（`POST /demo/actions/set-clock-mode`，立即生效、不用重启）即可，讲完再切回真实时间 | `POST /demo/actions/set-clock-mode`、`POST /demo/actions/tick {minutes:60}`、`POST /demo/actions/advance-to-less`、`GET /audit-logs` |
| 4:50–5:00 | 收尾 | 效率对比表（真实实测，§17）+ 那句核心口径 | `docs/demo-metrics.md` |

## 4. Demo 控制接口（§13.4，演示专用）

```http
POST /api/v1/demo/actions/set-clock-mode {clock_mode}  # 运行时切换 真实时间(system) / 虚拟时钟(replay)，立即生效、不用重启
POST /api/v1/demo/actions/tick {minutes:60}       # 推进时钟（需先切到虚拟时钟；system 下 409 DEMO_CLOCK_DISABLED）
POST /api/v1/demo/actions/advance-to-less         # 一步推到送达并自动关闭（同上，依赖虚拟时钟）
POST /api/v1/demo/actions/set-clock {target_utc}  # 时间跳转（同上，仅虚拟时钟）
POST /api/v1/demo/actions/reset {scenario:"case-a"}# 重建 seed（3 秒恢复；两种时钟模式都可用）
GET  /api/v1/demo/state                           # base_date / offset_minutes / ai_mode / clock_mode / seed_available
```

> 需登录并带 `Authorization: Bearer <token>` 与 `X-Workspace-Id`（`demo` 路由要求 `DEMO_CONTROL` 权限，见 `app/api/v1/demo.py`）。

## 5. 翻车恢复（预判面试现场会出的事）

| 故障 | 现场处理（<10s） | 兜底 |
|---|---|---|
| 前端页面数据不对/白屏 | F5 刷新（轮询模型无长连接状态） | `POST /demo/actions/reset` 后刷新 |
| 演示数据被上一轮改乱 | 一键 reset 重建 seed + 时钟归零 | `pwsh -File scripts/seed.ps1 -InitSchema` |
| 网络/额度问题（live 模式） | 切回 `AI_MODE=replay` 重启后端 | 默认就是 replay，现场无需切换 |
| AI 分析报错 | 页面提示"AI 暂不可用，可重试或手工处理"；点重试或直接人工处理 | 异常仍可由人工 resolve/close（§11.1 第 7 条） |
| 端口占用 | 改 `-BackendPort/-FrontendPort` 或关掉旧窗口 | `scripts/dev.ps1` 启动前会检测端口占用并报错 |
| 后端起来但连不上库 | 确认 `MySQL80` 服务；首次需执行 `scripts/init_db.sql` | `-Database Sqlite` 仅用于验收，不建议演示 |
