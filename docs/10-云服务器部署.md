# 10 · 云服务器部署（第一版）

> 目标：一台干净的云主机上把 LogiOps 跑起来，浏览器打开 `http://<公网IP>` 就能演示。
> 前提：**本机没有 Docker**，所以 `docker-compose.yml` / 两个 Dockerfile 从没在真机跑过 —— 我做了静态核对并修掉了 3 个必踩的坑（见「附录 B」）。第一次构建/启动如果报错，把命令输出发我，我来定位。

---

## 0. 先说走哪条路

| 路径 | 适合 | 步骤量 |
|---|---|---|
| **A. Docker Compose（推荐）** | 干净的 Ubuntu 云主机，想最快上线 | 5 条命令 |
| B. 手工装（MySQL + Python + Node + nginx + systemd） | 机器不给装 Docker，或你要自己控 nginx / TLS | 20+ 条 |

两条路跑起来的是**同一套代码**，功能完全一致。下面 A 是主线，B 作为兜底方案放在第 3 节。

---

## 1. 买机器 + 开端口（5 分钟）

1. **规格**：2 核 2G 起。构建前端（Node）和后端依赖最吃内存，**1G 很容易在 `pnpm build` 阶段被 OOM 杀掉**；如果只有 1G，先加 2G swap：
   ```bash
   sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   ```
2. **系统**：Ubuntu 22.04 或 24.04（下面命令都按 Ubuntu 写）。
3. **安全组 / 防火墙**：只放
   - `22`（SSH，强烈建议限制成你自己的 IP）
   - `80`（要 HTTPS 再加 `443`）
   **不要**对外开 `3306 / 3307 / 8000` —— compose 里我已经把数据库和 API 都绑到 `127.0.0.1`，外面只需要 80。
4. **域名（可选）**：A 记录指向公网 IP；没有域名就直接用 `http://<IP>`（`CORS_ORIGINS` 填这个地址即可）。

## 2. 路径 A：Docker Compose（推荐）

### 2.1 装 Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
newgrp docker            # 或者断开重连，让 docker 组生效
docker version && docker compose version
```
> 国内机器拉镜像慢，可参考「附录 A」加加速器。

### 2.2 拉代码

```bash
git clone https://github.com/zys2982-hash/logiops.git ~/logiops
cd ~/logiops
git log --oneline -1      # 确认拿到的是最新提交
```
> 私有仓库用 PAT：`https://<用户名>:<token>@github.com/zys2982-hash/logiops.git`

### 2.3 配置根目录 `.env`（**必做**）

```bash
cd ~/logiops
cp .env.example .env
openssl rand -hex 32       # 把输出填进 .env 的 SECRET_KEY
```

编辑 `~/logiops/.env`，至少改这几行：

```
SECRET_KEY=<上面生成的随机串>
CORS_ORIGINS=http://<公网IP>          # 有域名就写 http://your.domain 或 https://your.domain
MYSQL_ROOT_PASSWORD=<强口令>
MYSQL_PASSWORD=<强口令>
WEB_PORT=80
```

三个注意点：

- **别把本机的 `backend/.env` 传上来**（里面有你真实的 DeepSeek key）。云上的 `LLM_API_KEY` **留空** —— `AI_ENABLED` 默认关闭，AI 相关功能本来就不跑；`.env` 里的 `DATABASE_URL` / `TEST_DATABASE_URL` 是给"本机直跑后端"用的，compose 会用自己的值注入，**不用改**。
- 你改了 `MYSQL_PASSWORD`，compose 里的 `DATABASE_URL` 会自动跟着用新口令（我改成从同一个变量取了）。
- 想用 5173 这种端口就设 `WEB_PORT=5173`（默认 80）。

### 2.4 构建并启动

```bash
cd ~/logiops
docker compose up -d --build        # 第一次要装依赖 + 编译前端，2~5 分钟
docker compose ps                    # mysql / backend 应 healthy，frontend running
docker compose logs -f backend       # 看启动日志，Ctrl+C 退出
```

**验证**：
```bash
curl -s http://127.0.0.1/api/v1/healthz
# 期望：{"status":"ok","db":true,...}
```

### 2.5 造演示数据（**必做**，否则列表是空的）

```bash
docker compose exec backend python -m app.seed --reset --demo
```
- 默认规模 `compact`（3 张订单 + 3 张异常，界面清爽）。
- 想要 1000 单完整规模：`.env` 里加 `SEED_SCALE=full` → `docker compose up -d` → 再重跑上面那条 seed 命令。

### 2.6 打开验收

| 检查 | 地址 / 操作 |
|---|---|
| 前端 | `http://<公网IP>` |
| 登录 | `owner@logiops.dev` / `Demo@12345`（还有 admin / operator / viewer 同口令） |
| 接口文档 | `http://<公网IP>/docs` |
| 业务时间 | 顶部横幅的秒在跳（真实时间模式） |
| 演示工具 | 用 owner/admin 登录后可用「重置数据 / 状态直设」 |

## 3. 路径 B：手工装（不用 Docker）

### 3.1 系统依赖

```bash
sudo apt update
sudo apt install -y mysql-server nginx git curl
# Python 3.12：Ubuntu 24.04 自带 python3.12；22.04 建议用 uv 管理
curl -LsSf https://astral.sh/uv/install.sh | sh && source ~/.bashrc
```

### 3.2 建库建号

```bash
cd ~/logiops
sudo mysql < scripts/init_db.sql        # 建 logiops / logiops_test 两个库 + 账号（幂等）
# 改掉弱口令（强烈建议）：
sudo mysql -e "ALTER USER 'logiops'@'localhost' IDENTIFIED BY '<强口令>'; FLUSH PRIVILEGES;"
```

### 3.3 后端

```bash
cd ~/logiops/backend
uv sync --frozen --no-dev
cp ../.env.example .env
# 编辑 .env：SECRET_KEY=<随机串>；DATABASE_URL 用 <强口令>；CORS_ORIGINS=http://<公网IP>
uv run alembic upgrade head
uv run python -m app.cli init-schema          # 兜底建表 + 中文 FULLTEXT(ngram) 索引
uv run python -m app.seed --reset --demo
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000   # 先手工前台跑通，Ctrl+C 停
```

跑通后交给 systemd（`sudo nano /etc/systemd/system/logiops-api.service`）：

```ini
[Unit]
Description=LogiOps API
After=network.target mysql.service

[Service]
User=<你的用户名>
WorkingDirectory=/home/<你的用户名>/logiops/backend
Environment=PYTHONUNBUFFERED=1
ExecStart=/home/<你的用户名>/logiops/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now logiops-api
systemctl status logiops-api
```

### 3.4 前端构建 + nginx

```bash
cd ~/logiops/frontend
corepack enable
corepack pnpm install --frozen-lockfile
corepack pnpm run build                # 产物在 dist/
sudo mkdir -p /var/www/logiops && sudo cp -r dist/* /var/www/logiops/
```

`sudo nano /etc/nginx/sites-available/logiops`：

```nginx
server {
    listen 80;
    server_name _;

    root /var/www/logiops;
    index index.html;

    # 压缩与缓存：JS/CSS 不加压会原样发（默认只 gzip text/html），
    # 一次访问 1.75MB → gzip 后 0.49MB；带 hash 的资源可长缓存，重复访问几乎不耗流量
    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;

    location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }

    # SPA（Vue Router history 模式）：刷新页面不回 404
    location / { try_files $uri $uri/ /index.html; }

    # 前端统一走 /api/v1
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # 接口文档（Swagger 会再取 /openapi.json）
    location /docs { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; }
    location /openapi.json { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; }
}
```
```bash
sudo ln -sf /etc/nginx/sites-available/logiops /etc/nginx/sites-enabled/logiops
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

## 5. 常见坑（按现象查）

| 现象 | 原因 / 处理 |
|---|---|
| `docker compose ps` 里 backend 一直 **unhealthy** | 健康检查路径写错会 404（已修成 `/api/v1/healthz`）。若仍失败，看日志是不是连不上 MySQL（口令不一致 / mysql 还没起来） |
| 构建前端时进程被 **Killed** | 内存不够 → 加 swap（§1）或换 2G+ 机器 |
| 页面能开但接口 502 | 后端没起来 / 端口不对：`docker compose logs backend`；手工装时检查 `systemctl status logiops-api` |
| 刷新子页面 **404** | nginx 少了 SPA 回退 `try_files $uri $uri/ /index.html` |
| 登录报 **401/403** 或跨域 | `CORS_ORIGINS` 与访问地址不一致（带协议、带端口都要一致） |
| 中文变问号/乱码 | MySQL 不是 `utf8mb4`；compose 已配，手工装请确认建库用了 `utf8mb4_0900_ai_ci` |
| 演示数据是空的 | 忘了 §2.5 的 seed；或 seed 报错（多半是库连不上或 FULLTEXT 建索引失败，后者只告警不阻塞） |
| 想重新造一遍演示数据 | `docker compose exec backend python -m app.seed --reset --demo`（会清空该工作区业务数据） |
| 端口 80 被占 | `.env` 里设 `WEB_PORT=8080`，并把安全组对应放开 |
| 服务器重启后服务没起来 | compose 已设 `restart: unless-stopped`；手工装别忘了 `systemctl enable` |

## 6. 上线之后可以继续做的（都不是必须）

1. **HTTPS**：宿主机装 `certbot`，把 §3.4 的 nginx 站点加上 443（或用云厂商的 LB/证书）。Docker 路径就用宿主机 nginx 反代 `127.0.0.1:80` 再签证书。
2. **换掉演示口令**：4 个演示账号都是 `Demo@12345`（`backend/app/seed/catalog.py` 的 `DEMO_PASSWORD`），公开演示站建议改掉后重新 seed。
3. **备份**：`mysqldump -ulogiops -p logiops > backup.sql`（容器路径用 `docker compose exec mysql mysqldump ...`），配个每日 cron。
4. **收紧暴露面**：不想公开接口文档就在 nginx 里给 `/docs`、`/openapi.json` 加 `allow/deny`。
5. **日志**：`docker compose logs` 默认会无限增长，给 Docker 配 `log-opts` 限制大小。

## 附录 B：本轮为了让部署能跑通，我改了这些

| 文件 | 改动 | 为什么 |
|---|---|---|
| `backend/Dockerfile` | 健康检查 `/healthz` → `/api/v1/healthz` | 项目没有裸 `/healthz` 路由（实测 404），容器会一直标 unhealthy |
| `docker-compose.yml` | 同上修健康检查；MySQL 口令改为从 `${MYSQL_PASSWORD}` 取并按需拼 `DATABASE_URL` | 原来是硬编码弱口令，云上不好换 |
| `docker-compose.yml` | 端口：前端 `${WEB_PORT:-80}:80`；后端/MySQL 绑 `127.0.0.1` | 公网只暴露 80；数据库和 API 不对公网开放 |
| `frontend/Dockerfile` | nginx 增加 `/docs`、`/openapi.json` 反代 | 后端不再对公网开 8000，接口文档仍能从 80 端口访问 |
| `frontend/.dockerignore`、`backend/.dockerignore`（新增） | 排除 `node_modules`/`dist`/`.venv`/`.env` 等 | 前端 Dockerfile 有 `COPY . .`，不排除会把 `node_modules` 全打进构建上下文（慢且可能出错）；顺带防止把带真实 key 的 `.env` 打进镜像 |
| `frontend/Dockerfile`、本文 §3.4 | nginx 开 gzip（JS/CSS/JSON）+ 静态资源长缓存 | 官方 nginx 默认只 gzip `text/html`，JS/CSS 是原样发的：一次访问 1.75 MB → 0.49 MB |

## 附录 C：一次访问多少流量 / 选服务器时看这个

实测（`frontend/dist` 构建产物，2026-10-06）：

| | 原始 | gzip 后 |
|---|---|---|
| 主 JS `index-*.js` | 1316 KB | 423 KB |
| 主 CSS | 356 KB | 48 KB |
| **打开一次页面合计** | **≈ 1.75 MB** | **≈ 0.49 MB** |
| 重复访问（资源已缓存） | 几十 KB（只有 index.html + 接口 JSON） | 同左 |

由此算：

- **固定带宽 3 Mbps**（≈ 375 KB/s）：gzip 后首屏 ≈ 1.3 秒；没开 gzip ≈ 4.7 秒。演示时 1~3 人同时看没问题。
- **按流量 0.8 元/GB**：gzip 后一次冷访问 0.49 MB = 0.00048 GB ≈ **¥0.0004（不到 1 分钱）**；不开 gzip（1.75 MB）≈ ¥0.0014。**重复访问几乎为 0**（资源已缓存）。
  量级参考：1 000 次冷访问 ≈ ¥0.4；10 000 次 ≈ ¥4；10 万次 ≈ ¥39。
- **盈亏平衡点**：99 元/年 ÷ 0.8 元/GB ≈ **124 GB/年**，即 gzip 后约 **25 万次冷访问** —— 正常演示用量差着 3 个数量级。
- 首次部署要在服务器上下载镜像 + 依赖约 **1 GB**：国内云一般**只收公网出流量**，这 1 GB 入流量不计费；但 3 Mbps 的线路下载需 **40~60 分钟**，记得用 `tmux` / `nohup` 跑，别让 SSH 断开把构建掐了。
