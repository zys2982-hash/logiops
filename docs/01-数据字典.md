## 1. 通用约定（对应 §7.1，实现在 `backend/app/db/base.py`）

| 约定 | 实现 | 为什么 |
|---|---|---|
| 主键 | `PkMixin`：`BigInteger` + sqlite 变体 `Integer`，自增 | 同一套模型既能跑 MySQL 也能跑 sqlite（测试/离线验收） |
| 时间戳 | `TimestampMixin`：`created_at` / `updated_at`，默认 `utcnow_naive()` | 走 `core/clock.py`，replay 时钟下即"业务时间"，保证可复现（§13.1） |
| 多租户 | `WorkspaceScopedMixin`：`workspace_id` 外键 + 索引 | Repository 统一注入 `workspace_id`，跨租户访问一律 404（§9.1） |
| 乐观锁 | `VersionMixin`：`version`（默认 1） | 写操作带 `expected_version`，不匹配 → 409 `OPTIMISTIC_LOCK_CONFLICT`（§10.1） |
| 软删除 | `SoftDeleteMixin`：`is_deleted` | 列表默认过滤；不提供回收站（§3.2 有意省略） |
| 操作者留痕 | `AuditCreatorMixin`：`created_by` | 配合 `source`（MANUAL / APPROVED_AI / SYSTEM）做审计（§11.5） |
| 枚举 | `VARCHAR + StrEnum`，**不用 MySQL ENUM** | 加减枚举值不改表结构（ADR-A10） |
| 命名规范 | `MetaData(naming_convention=...)` | 索引/唯一键/外键命名稳定，迁移 diff 干净 |

**存 UTC、展示 Asia/Shanghai**（ADR-A9）：DB 与 API 都是 UTC，本地化只发生在前端 `utils/datetime.ts`。

## 2. 22 张表分组（对应 §7.3；字段见 §7.4）

| 分组 | 表 |
|---|---|
| 身份与租户（4） | `user`、`workspace`、`workspace_member`、`system_setting` |
| 主数据（5） | `customer`、`carrier`、`vehicle`、`driver`、`sla_rule` |

## 4. 可执行校验命令（都能直接跑）

```powershell
cd backend

# 1) 模型数量与表名（应为 22）
uv run python -c "from app.models import TABLES;print(len(TABLES));print(TABLES)"

# 2) 建表（含 MySQL FULLTEXT ngram 中文索引）——幂等，可重复执行
uv run python -m app.cli init-schema            # 加 --drop 先删表
uv run alembic upgrade head                     # 迁移路径（与 init-schema 结果应一致）

# 3) 直连数据库核对表/索引（本机 MySQL，路径 A）
mysql -ulogiops -plogiops -h127.0.0.1 logiops -e "SHOW TABLES; SHOW INDEX FROM knowledge_chunk WHERE Key_name='ft_knowledge_chunk_content';"
mysql -ulogiops -plogiops -h127.0.0.1 logiops -e "SHOW CREATE TABLE exception_case\G" | Select-String "version|workspace_id"

# 4) 迁移可回滚性（§15 D1 验收物：upgrade/downgrade 都能跑）
uv run alembic downgrade base; uv run alembic upgrade head

# 5) 模型层单测（约束/枚举/乐观锁）
uv run pytest tests/unit -q
```

## 5. 改表流程（数据字典是契约，不是注释）

1. 改 `backend/app/models/*.py`（字段定义与基线 §7.4 同步）；
2. `uv run alembic revision --autogenerate -m "描述"`，**人工 review** 生成的迁移（尤其默认值、索引、FULLTEXT 这类方言相关 DDL）；
3. `uv run alembic upgrade head` 验证，再 `downgrade -1` 验证可回滚；
4. 同步更新基线 §7.4 字段表（以及本文"分组/关系"若受影响的部分）；
5. 提交前跑 `uv run pytest -q`（conftest 会用 sqlite 临时库重建全部表，等于一次最小迁移回归）。

## 6. 已知取舍

- `sla_rule` 只支持 DEFAULT / CUSTOMER_LEVEL / CUSTOMER 三种 scope，且**不考虑节假日**（24×7，ADR-A14）；
- 异常 `CLOSED` 为终态，**不提供 reopen**（ADR-A11）；误判用 `close(reason_code=INVALID)` 留痕后新建；
- `knowledge_chunk` 的全文索引是 MySQL 专有（`WITH PARSER ngram`）；sqlite 模式自动退化为 LIKE 兜底（§11.6）。
