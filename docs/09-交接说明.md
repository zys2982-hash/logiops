## 2. 当前业务口径（用户亲口定的，别按旧文档改回去）

### 2.1 风险模型：**一张异常单只受一个问题影响**
| 问题类型 | 分数 | SLA 影响 |
|---|---|---|
| **车辆故障单** `VEHICLE_BREAKDOWN` | 车辆故障 **1** + 客户等级（VIP **1** / SVIP **2**）= 1~3 | **完全没有**：详情页不显示 SLA 卡；`sla_delay_minutes=None`、`sla_breached=False`（列表自 2026-10-06 起不再显示 SLA 列） |
| **延误单** `DELAY_RISK` | 延误档位（≤120=1 / 121–360=2 / >360=3）+ 客户等级，封顶 4（**不再重复加"违约 1"**） | 有：SLA 卡内容 = **承诺到达 / 实际送达 / 延误时长** |

- ⚠️ **演示数据里没有 SVIP 客户了**（2026-10-06 用户口径：「把 svip 用户改成 vip」）：原来唯一的 SVIP 客户「亚太供应链」已改成 **`VIP-04` / VIP**（种子、演示重建脚本、真库都改了）；风险模型仍保留 `SVIP +2` 的代码与枚举（历史数据、接口仍可用，只是演示不再产生）。

- 等级：0→LOW，1–2→MEDIUM，3→HIGH，≥4→CRITICAL（`MAX_SCORE=4`）。**未结束的异常最低 MEDIUM**（因子至少 1 分才会建单）；LOW/0 只出现在"已结束"的**当前风险**里。**例外**：2026-10-06 起收口全靠人工，所以"车已修好、单子还没人点解决"时，未结束的单可以合法地显示 0 分（因子按现状消失，见 §2.5 第 3 条）。
- 因子代码：车辆单 = `VEHICLE_BREAKDOWN`(+客户等级)；延误单 = `DELAY_BASE`(+客户等级)。旧的 `SLA_BREACH` 因子已取消。

### 2.2 建单时机
- **在途不报延误**：检测规则只剩 `STALL_OVER_THRESHOLD`（轨迹停滞 ≥120min → 车辆故障单）。旧的 `ETA_BREACH_SLA` 已下线（枚举保留仅供历史数据读取）。
- **延误只在送达时判定**：订单点「送达」→ 程序只做两件事：①按 `实际送达 − 承诺送达 > 规则允许延迟` 判定，超了才自动建延误单（`status=DETECTED`、`detected_by=SYSTEM`、`detection_rule=DELIVERED_BREACH`），没超**不建单**；②把送达那刻还开着的每张单的「车辆故障」因子对齐现状。**不再替用户收口任何单**（见 §2.5）。

### 2.3 修改功能（替代旧的"录入延误"）
- 入口：① 订单详情页「修正实际送达时间」（订单已送达时显示，需 `order.manage`）；② 异常详情页 SLA 卡的「修改」。
- 接口：`PATCH /api/v1/orders/{id}/delivered-at`，body `{delivered_at, note?}`；未送达 → 409；早于派车 → 422；OPERATOR → 403。写审计 `order.delivered_at_corrected`。
- 改完立即重算：仍违约 → 重算延误/分数并写 `ETA_UPDATED`；**不再违约 → 也只重算 + 写 `ETA_UPDATED`（note 带「已不再违约；是否收口由人工决定」），状态不变**（2026-10-06 起不自动收口，等人工点「关闭 / 解决」）。
- 旧的「录入延误」已删除：路由 `POST /exceptions/{id}/delay`、`ExceptionDelay`、`ExceptionCreate.delay_minutes`、`set_delay`/`_apply_manual_delay` 全部移除。

### 2.5 异常状态只由人工触发（**2026-10-06 用户新口径**）
用户原话：「异常的关闭、解决等状态应该由我自己选择触发，不要让程序通过触发一些特定条件自己触发」。

**已下线的 5 处自动收口**（都在后端，别再加回来）：
| 原来在哪 | 原来干了什么 |
|---|---|
| `OrderService.mark_delivered` | 送达即闭环：处理中→已解决 / 待确认→已关闭(DELIVERED) |
| `OrderService._settle_delivered_delay` | 改送达时间后「不再违约」→ 自动解决 / 自动归档为误报(INVALID) |
| `tick._resolve_cleared_risks` | 轨迹恢复、风险解除 → 自动 RESOLVED（现改为只刷新数字，函数改名 `_refresh_open_cases`） |
| `ExceptionService.auto_close_resolved` + `tick.run_tick` | 已解决满 24h → 自动 CLOSED（方法已删除） |
| `OrderService.cancel` | 订单取消 → 连带关闭它的异常单（该方法目前无接口入口，仍一并去掉） |

**手动出口（都在界面上，你要的全都有）**：
- **异常中心 → 异常详情页**：「解决」（必填 note）、「更多」→「关闭 / 强制关闭（ADMIN，需 `exception.force_close`）」、「车辆已修复（只去掉车辆故障因子，不结束异常）」；
- 演示页：订单与异常的「状态直设」（`POST /demo/actions/force-status`，跳过状态机但写审计）；
- 演示页「推进到送达并关闭」＝ `POST /demo/actions/advance-to-less`：**推进时钟 + 以人工起点显式关闭目标异常**（`advance_until_delivered(close_target=True, actor_id=当前用户)`，审计 actor 是人）。纯 `tick` 不再关任何异常。

**⚠️ 订单页的处置入口已全部撤掉**（2026-10-06 第二批口径，见 §2.6）：订单详情页只保留「录入异常」，原来的「结束异常 / 归档异常 / 车辆已修复」三块都删了 —— 结束异常必须去异常中心。

**连带改成的新口径**：
1. **同一订单同一问题类型最多一张"未关闭"单**（原来是"一单一未结束单"）：允许「未关闭的车辆单 + 未关闭的延误单」并存，各管一个问题。仓储新增 `find_open_by_order_and_type` / `list_open_by_order`；判重、建延误单、手工建单都改成按类型查（`OPEN_EXCEPTION_EXISTS` 文案带类型）。
   注意 `OPEN_EXCEPTION_STATUSES`（后端判重用）**含 `RESOLVED`**：已解决未归档也算占着该类型的名额，只有 `CLOSED` 才释放 —— 前端订单页的判重必须同口径，否则点了必然 409。
2. **送达 / 关闭 / 取消的订单允许带未结束异常**：那正是"等你处置"的状态（自检脚本 §4 不变量已放宽）。
3. **车单不收口 → 因子按现状算**：送达会把车放回 IDLE（订单跑完），于是「车辆故障」因子消失（信号级闭环），那张仍开着的车单**当前风险可能显示 0 分**——不是 bug，是"当前风险按现状推导 + 状态由人决定"的必然结果；点「解决」才真正结束（此时订单已送达 → 车辆释放为 IDLE 而不是回原状态）。
4. `sla_breached` 可能合法地翻成 `False`（改过送达时间后），所以自检脚本不再要求"延误单必须一直在报违约"，改为**按规则核对一致性**（`sla_breached == 延误 > 规则允许延迟`）。
5. 延误单**已解决（RESOLVED）也仍占名额**：此时再改送达时间并改回"超时"，走的是**重算**（`ETA_UPDATED`），不会新建第二张延误单；只有那张单被**归档成 CLOSED** 之后，同类型才会允许再建。

### 2.4 其它已定口径（早前几轮）
- **异常状态只有 4 个**：待确认 `DETECTED` → 处理中 `PROCESSING` → 已解决 `RESOLVED` → 已关闭 `CLOSED`（`CONFIRMING` 并入处理中；`ANALYZING` 随 AI 停用废弃；旧值读取时归一显示为「处理中」）。
- **`type` vs `current_type`**：`type` = 建单原因（历史，不变）；`current_type` = **当前问题**：未结束的单里，还带「车辆故障」因子 → 车辆故障，**没有该因子时沿用建单原因**（2026-10-06 修正：原来无条件兜底成"延误风险"，会把"车已修好、还没人收口"的车辆故障单错标成延误 —— 2026-10-05 起车辆故障单不做 SLA 判定，永远不会带延误因子）；已结束的单也沿用建单原因。界面一律显示 `current_type`（列表「异常类别」列、详情页标签、订单时间线）。
- **`level/risk_score` vs `current_level/current_risk_score`**：后者是**当前风险**，已解决/已关闭 → `LOW/0`；前者是历史存档，详情页「风险等级（历史判定）」卡片用。

## 5. 环境/工具坑（踩过的，别再踩）

1. **不要用 PowerShell 改文本文件**（`Set-Content`/`Get-Content -Raw | ... | Set-Content` 会把 UTF-8 中文写成乱码/UTF-16）——用编辑工具，或整文件重写。本次就是这样弄坏过一个测试文件，靠 `git checkout -- <file>` 恢复。

4. 后端 `--reload` 在本机会卡（见 §1）；改完代码手动重启（几秒）。
5. 会话里起的前后端是**后台任务**，回合结束可能被回收 —— 新对话里先 `Get-NetTCPConnection -LocalPort 8000,5173` 看一眼，没跑就按 §1 重启。
