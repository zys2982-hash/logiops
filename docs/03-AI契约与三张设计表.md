# 03 · AI 契约与三张设计表（要点与校验）

> **唯一真相**：[`00-项目基线-MVP.md`](00-项目基线-MVP.md) **§11**（§11.1 边界与原则 / §11.2 三张设计表 / §11.3 有界循环 / §11.4 Prompt 版本 / §11.5 HITL 执行链 / §11.6 知识检索 / §11.7 模型成本脱敏 / §11.8 降级）。
> 本文只讲"边界怎么落、怎么验"，**不重复三张表的字段级内容**（§11.2 表 1/表 2/表 3 是唯一定义）。
> 代码侧对应：`backend/app/ai/`（llm_client / prompts / tools / agent / retriever / guard）。

## 1. 七条硬约束（§11.1，违反即 review 不过）

1. **AI 全只读**：`ai/tools/` 里的 7 个工具全是读操作；AI 模块禁止 import Repository 与 Session；
2. **AI 不决定等级**：`level` 由 §8.6 规则计算（`risk_factors` 可解释），LLM 只能给摘要/原因/建议；
3. **AI 不编事实**：通知草稿里的 ETA / 订单号 / 客户名 / 延误分钟必须来自 Tool 返回，校验阶段逐字段比对（正则抽取 + 事实比对）；
4. **输出必须过 Pydantic schema**：失败 → 修复重试 1 次 → 仍失败 → 任务 `FAILED` + 降级；
5. **写意图一律变审批单**：AI 输出 `suggestions[]` → 后端生成 `approval(PENDING)` → 人批准 → 执行器落库；
6. **每次分析落库**：`ai_analysis` 记录 `prompt_version / raw_output / tokens / 耗时 / 工具步骤`，可按 case 复盘；
7. **AI 失败不阻塞业务**：异常仍可由人工 `resolve`/`close`（"人在环上"的证明）。

## 2. 三张设计表怎么读（§11.2）

| 表 | 内容 | 落地位置 | 关键点 |
|---|---|---|---|
| 表 1 · AI 输入 | 3 个任务（T1 消息解析 / T2 异常分析 / T3 通知草稿）的触发点、输入来源、入参、PII、幂等键 | `ai/prompts/*/v1.md` 的模板变量 + `ai/agent` 的入参装配 | 幂等键 = `input_hash`，replay 与重试都靠它；手机号先经 `core/masking.py` |
| 表 2 · AI 输出（JSON Schema） | 每任务字段、类型、必填、校验规则、是否写库 | `app/schemas/ai.py`（`additionalProperties=false`） | 三条"必须相等"校验：`impact.delay_minutes` ≈ 后端 `sla_delay_minutes`（±5min）、`sla_breached` 必须一致、`evidence_refs[].id` 必须存在于本次 Tool 返回 |
| 表 3 · 所需业务数据与 Tool | 7 个只读 Tool 的用途/入参/出参摘要/底层 Service/权限 | `app/ai/tools/` | **没有写工具**：`create_followup_task` 已从 Tool 列表移除（ADR-A5，原稿矛盾点） |

T3 是**由 T2 自动串联**的（不用人工再点一次）：输入是"系统已确认的结构化事实"，不是原始文本——这是防幻觉的关键设计。

## 3. 有界 Agent 循环（§11.3）

```text
形态       单轮 tool-calling 循环（手写，不用 LangGraph；ADR-A6）
最大步数   8（含最终输出）；总超时 90s（LLM 单次 60s）
工具白名单 仅 §11.2 表 3 的 7 个
终止条件   产出合法 JSON / 超步数 / 超时 / 连续两次校验失败
降级       ai_analysis.status=FAILED + error_code（LLM_UNAVAILABLE / AI_OUTPUT_INVALID）；
           异常状态由 ANALYZING 回退 CONFIRMING；前端提示"AI 暂不可用，可重试或手工处理"
重放       AI_MODE=replay 时按 input_hash 读 fixtures（含 steps），完全不走网络
```

## 4. Prompt 版本管理（§11.4）

- 目录：`backend/app/ai/prompts/{t1_parse_message,t2_analyze_exception,t3_draft_notice}/v1.md`；
- `prompt_version="v1"` 落库，可对比不同版本效果；
- 模板变量用 `{placeholder}` 显式声明，并有单测断言"模板变量 = 代码传入变量"（防漏传导致幻觉）；
- T1 放 3 个 few-shot（含"晚上 8 点"这类相对时间解析）；T2 **不放假数据示例**，避免模型抄示例。

## 5. 人工确认执行链（§11.5）

```text
T2 输出 → suggestions 逐条生成 approval(PENDING)（1 建议 = 1 审批单）
人批准   POST /api/v1/approvals/{id}/approve {expected_version, final_payload}   # 可改 AI 建议
执行器   事务内：校验 → 按 action_type 分发（UPDATE_ETA / CREATE_FOLLOWUP / SAVE_NOTICE / SEND_NOTICE / CLOSE_EXCEPTION）
         → 写异常时间线 + 审计（source=APPROVED_AI，ai_payload 与 final_payload 双留痕）→ approval=EXECUTED
失败     approval=FAILED + execution_result.error，可 POST /approvals/{id}/execute 重试（retry_count+1）
不执行   拒绝（REJECTED，必填 reason）/ 过期（EXPIRED，24h）都不产生任何业务副作用
```

## 6. 知识检索（§11.6，不引向量库）

- 语料：`backend/app/knowledge/*.md`（5 篇）；按 `##` 小节切分，超 500 字再切段落，保留 `section_path`；
- 索引：MySQL `FULLTEXT(content) WITH PARSER ngram`（`init-schema` 自动创建；sqlite 模式退化 LIKE 兜底）；
- 检索：`MATCH ... AGAINST (:q IN BOOLEAN MODE)`，无命中走 LIKE 兜底，仍为空则返回 `[]` 并降低建议置信度；
- **来源可点**：每个 chunk 返回 `doc_title / section_path / chunk_id`，T2 的 `evidence_refs` 必须引用真实 `chunk_id`；
- 可切换：保留 `KnowledgeService.search` 接口，P2 可换 Qdrant 而不动 Agent（ADR-A4）。

## 7. 模型、成本与脱敏（§11.7）

| 项 | 值 |
|---|---|
| 模型 | `LLM_MODEL=deepseek-chat`（OpenAI 兼容端点）；换 `LLM_BASE_URL/LLM_MODEL` 即可切 qwen/gpt，代码零改动 |
| 成本 | 单次 ≤8k in / 4k out；演示默认 replay（0 成本）；live 模式每日 ¥20 上限，超限直接降级 |
| 脱敏 | 写 prompt 前过 `core/masking.py`：手机号 `138****0001`、邮箱 `a***@x.com` |
| 日志 | 每次调用记 model / prompt_version / tokens / latency / raw_output（原始文本入库便于复盘，API 不暴露内部细节） |
| 合规 | seed 全为虚构数据；接真实企业数据需先做数据出境与保密评审（本作品不涉及） |

## 8. 可执行校验命令

```powershell
cd backend

# 1) AI 层单测：解析抽取 / 工具顺序 / 步数上限 / 非法 JSON 重试 / 超时降级 / 事实一致性拦截 / prompt 变量完整性
uv run pytest tests/ai -q

# 2) 硬约束 3：AI 模块不得 import Repository / Session（层级检查）
Get-ChildItem app\ai -Recurse -Filter *.py | Select-String -Pattern "from app\.repositories|import Session|sessionmaker" | ForEach-Object { "VIOLATION $($_.Path):$($_.LineNumber)" }
# 若 backend/scripts/check_layering.py 已就位，用它做完整分层检查：
if (Test-Path scripts\check_layering.py) { uv run python scripts\check_layering.py }

# 3) replay fixtures 是否齐备（验收脚本也查这一项，缺失会 exit 2）
Get-ChildItem tests\fixtures\ai -Filter *.json | Measure-Object | Select-Object -ExpandProperty Count

# 4) 离线回放演示（不联网、0 成本、结果确定）：AI_MODE=replay 为默认，直接跑
uv run pytest tests/ai -q -k replay
uv run python -m app.seed --reset --demo     # seed 就绪后
# 全链路（建单→分析→审批→执行→送达→自动关闭）：
uv run python ..\scripts\acceptance_case_a.py run --out ..\artifacts\acceptance_run1.json

# 5) 切 live 模式（需要 LLM_API_KEY；只用于录制 fixtures，附录 D-B P4）
$env:AI_MODE='live'; $env:LLM_API_KEY='sk-...'; uv run pytest tests/live -m live -q
```
