# 08 · 时间与延误口径简化（已决议，待执行）

> 决议人：项目拥有者　｜　状态：**已确认口径，尚未开始改代码**
> 背景：现有"ETA 引擎 + 演示时钟 + 快照"三套时间概念并存，界面出现「承诺到达 / 当前 ETA / 预计到达」三个时间，
> 使用者反复表示"看不懂、不是同一个时间"。经讨论决定**删繁就简**，按真实项目口径重做。

## 1. 最终口径（已确认）

| 概念 | 谁提供 | 说明 |
|---|---|---|
| **承诺到达时间** | **规则算**（发车时间 + SLA 规则 `deadline_offset_hours`） | 保留。规则匹配顺序不变：`CUSTOMER` → `CUSTOMER_LEVEL` → `DEFAULT` |
| **当前时间** | **业务时间**（系统 now，`CLOCK_MODE` 决定真实/演示） | 界面只用于展示"现在几点"，不再有"当前 ETA"这个概念 |
| **延误时长** | **人工录入**（分钟数） | 人负责报事实：晚了多久 |
| **是否违约** | **规则判定**：`延误分钟 > 规则 max_delay_minutes` | 保留"等级/违约由规则算"的卖点；人工只填事实，不决定判定 |

**删除的概念**：订单 `current_eta_at` / `original_eta_at`、异常单 `expected_eta_at`、ETA 三算法（REPAIR_WAIT / MOVING_AVG_SPEED / FALLBACK）、轨迹 `speed_kmh`。

## 4. 取舍与风险（写清楚，避免以后被追问）

- **失去的能力**：不能再演示"ETA 随轨迹自动重算"；`tick` 推进的价值缩小到"检测 / 自动关闭 / SLA 违约升级"。
- **换来的一致性**：界面只有三个概念（承诺到达 / 当前时间 / 人工延误），不会再出现"两个时间不一样"的困惑。
- **历史数据**：现有库里的 ETA 字段值会被迁移丢弃（演示数据可重置，无需保留）。
- **保留不动的**：停滞检测（≥120min 自动建单，只用事件时间）、异常状态机、审批/执行器、审计、多租户隔离、限流。
